# Architecture

Flowmark is a local filesystem application packaged as one executable. The
binary contains the CLI, production web assets, server-side workspace access,
and the scheduler. It opens no non-loopback listener and requires no runtime
network service.

```text
Markdown/YAML workspace
        │
        ▼
validator + reference resolver ──► stable diagnostics / CLI schemas
        │ valid only
        ▼
filesystem repositories ◄──────► rule transaction engine
        │                              │
        ▼                              ▼
TanStack server functions       startup / midnight jobs
        │
        ▼
React board at 127.0.0.1
```

## Runtime boundary

`src/cli.ts` is the entry point. `serve` validates the workspace before
starting either the UI or background jobs. Foreground and daemon sessions share
`src/lib/session-supervisor.ts`, which owns the web server, rule jobs, control
endpoint, registry lifecycle, and graceful shutdown.

Release binaries use the adapter generated by `scripts/build-binary.ts`. It
embeds Nitro's handler and all production assets, then starts `Bun.serve` on an
available `127.0.0.1` port. Requests must carry the expected loopback Host and,
when present, same-origin Origin headers. Source development uses Vite, also
loopback-only.

`~/.flowmark/sessions.json` records running session metadata so `flowmark list`
and `flowmark stop` work from any directory. It is not authoritative and
contains no task semantics.

## Storage and validation

`src/lib/workspace/validator.ts` parses every source resource, verifies schema
version and fields, detects duplicate IDs, resolves references, and validates
the complete graph. Validation happens before repositories project data into
the UI.

Repositories under `src/lib/workspace/` translate the canonical format to the
small UI model. Writes use sibling temporary files, flush, rename, and
post-write validation. Markdown bodies are kept separate from frontmatter so
descriptions and comments survive structured edits. Multi-file mutations keep
an in-memory journal and restore every touched file if post-write validation
fails.

The schema catalog in `src/lib/workspace/schema-catalog.ts` exposes the current
contract through `flowmark schema`. Its tests ensure rule capabilities and
validator fields remain represented.

## Board and UI

TanStack Start provides file routing and server functions. The board is a React
application under `src/components/board/`. `src/lib/store.ts` owns optimistic
board state, persistence state, and drag/drop transitions. Only non-semantic UI
preferences may use browser storage.

Tailwind CSS v4 and semantic OKLCH tokens in `src/styles.css` implement eight
themes. The selected theme lives in `flowmark.yaml`, not local storage.

## Automation

Rules are authoritative YAML resources. Event rules are evaluated by the
bounded transaction engine in `src/lib/rule-engine.ts`. Derived events can
cascade, identical writes are no-ops, and repeated transaction states stop
loops deterministically.

`src/lib/workspace/rule-runner.ts` owns startup reconciliation, scheduled
rules, and local-midnight reconciliation. Resulting changes are persisted as
normal source-file changes.

## Disposable state

`.flowmark/` may contain caches, locks, job cursors, and UI runtime preferences.
Deleting it can cause a rebuild or loss of convenience state, but never loss or
reinterpretation of cards, rules, ordering, comments, or checklists.
